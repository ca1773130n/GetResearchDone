# Tesserae 0.9.0 Wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make GRD consume Tesserae 0.9.0's AgentRunbook distilled memory (`Runbook`/`Gotcha`) in the harness, surface the loud-extraction diagnostic, and enable distillation on GRD's compile.

**Architecture:** Python changes in `bin/harness_driver.py` (evidence filter + empty-findings hint), TS changes in `lib/research/tesserae.ts` (`--distill` compile flag) and `lib/research/retrieve.ts` (no-graph hint). `retrieve.ts` ranking stays node-type-agnostic, so distilled nodes surface for free. All changes degrade gracefully against an 0.8.x graph.

**Tech Stack:** Python 3 (`unittest`, monkeypatch-free graph fixtures), `autoresearch_core` `Finding` (kind is a `Literal`), TypeScript (jest), the `tesserae` CLI.

**Spec:** `docs/superpowers/specs/2026-06-14-tesserae-0.9.0-wiring-design.md`

```markdown
### Tesserae 0.9.0 AgentRunbook memory

Tesserae 0.9.0 distills cross-session `Runbook` (procedures) and `Gotcha`
(failure modes) nodes from your session findings. The GRD harness consumes them
as high-signal evidence. To populate them, set `distillation.enabled: true` in
your Tesserae project config (or run `tesserae refresh` with distillation), then
run a harness round. If a round skips with "not enough evidence", run
`tesserae config status` — a rate-limited backend can silently cache empty
extractions, which 0.9.0 now reports loudly.
```
