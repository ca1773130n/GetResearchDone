# Design: Wire Tesserae 0.9.0 (AgentRunbook memory + loud-failure awareness)

Date: 2026-06-14
Status: Approved (design); implementation plan pending.

Adopt the two GRD-relevant capabilities Tesserae 0.9.0 adds, on top of the
existing integration (GRD shells out to the `tesserae` CLI and reads
`.tesserae/graph.json`; it does **not** call `tesserae context`).

## Background

Tesserae 0.9.0 over 0.8.1 adds (PRs #35, #36):

1. **AgentRunbook multi-granularity memory** — new node kinds in the research
   graph: `Event` (per-transition), `Runbook` (distilled reusable procedure),
   `Gotcha` (distilled recurring failure mode), plus a `precedes` edge. Exact
   `node_type` values are `"Event"`, `"Runbook"`, `"Gotcha"`
   (`tesserae/research_graph.py:153-155`). Opt-in via `tesserae compile
   --distill` / config `distillation.enabled` / env `TESSERAE_RUNBOOK_DISTILLATION`
   (`tesserae/cli.py:1808-1810`); LLM-optional with a deterministic fallback;
   byte-idempotent. Tesserae's own retrieval gains `tesserae context
   --multi-pool` (`cli.py:1833`) that reserves budget for these nodes.
2. **Loud session-extraction failures + `tesserae config status`** — a
   rate-limited backend used to silently cache zero findings, producing "a graph
   with sessions but no decision findings." 0.9.0 stops caching FAILED chunks and
   prints a warning; `tesserae config status` shows the resolved provider +
   liveness. This is the exact trap that makes GRD's harness skip with "not
   enough evidence."

### GRD's current Tesserae surface (what we wire into)

- `lib/research/tesserae.ts` — shells `tesserae` with compile args
  `[...sources, '-o', graph, '--sqlite-output', sqlitePath, '--changed-only',
  '--canonicalize']`; reads `graph.json`. Used by the autoresearch loop.
- `lib/research/retrieve.ts` — reads `.tesserae/graph.json` directly and ranks
  **all** nodes (BM25-lite + PPR-lite + RRF). **No node-type whitelist**, so
  distilled nodes are retrievable for free once present in the graph. This is
  why GRD needs no `--multi-pool` call: GRD does its own retrieval.
- `bin/harness_driver.py` — `TesseraeFindings.findings()` reads
  `.tesserae/graph.json`, matching only `Session(Insight|Decision|Question|Todo|
  Hypothesis|Takeaway)` node types (`_FINDING_TYPE_RE`) / bare `kind` in
  `_FINDING_KINDS`. The harness graph is built by the **user's** `tesserae
  sessions-import` + `tesserae refresh`, not by GRD.

Key consequence: distillation derives `Runbook`/`Gotcha` from **session**
findings, so the value lands in the **harness** graph. GRD's job is to (a)
**consume** those nodes, (b) surface the loud-failure diagnostic, (c) enable
distillation where GRD does compile and document it where the user does.

## Scope

Modify: `bin/harness_driver.py`, `lib/research/tesserae.ts`,
`lib/research/orchestrator.ts` (or `ingest.ts`/`synthesize.ts` for the hint),
`tests/python/test_harness_conformance.py`, `tests/unit/research/tesserae.test.ts`,
`CLAUDE.md`, `docs/autoresearch-tutorial.md`.

Out of scope: calling `tesserae context --multi-pool` (GRD doesn't use Tesserae
retrieval); consuming `Event` nodes (per-transition, too granular/noisy for
self-improvement evidence); a `precedes`-edge traversal; new config knobs (the
"full adoption" option was not selected).

## Changes

### 1. Upgrade the installed Tesserae to 0.9.0 (environment step)
Install 0.9.0 from source (`/Users/neo/Developer/Projects/Tesserae`, version
0.9.0) over the current pipx 0.8.1: `pipx install --force` (or
`pip install -e .` in the active env). Verify `tesserae --version` reports 0.9.0
and `tesserae --help` lists `config status`, `--distill`. Re-run GRD's harness
python suites to confirm the additive schema didn't break graph.json reading.

### 2. Harness consumes `Runbook` + `Gotcha` (core value)
In `bin/harness_driver.py`, extend `TesseraeFindings.findings()`:
- Add a recognizer for distilled nodes: `node_type ∈ {"Runbook", "Gotcha"}`.
- Map to `Finding` with a valid `FindingKind` (kind is a `Literal`, so the raw
  strings cannot be used): `Runbook → "takeaway"`, `Gotcha → "insight"`.
- Preserve provenance by prefixing content: `content = f"[{runbook|gotcha}] " +
  <node content>`, so `evidence_md` shows the distilled origin.
- `source` = node id; `created_at` from the node if present (distilled nodes are
  often undated — the existing "undated evidence always passes the `since`
  cursor" rule applies, which is correct: a distilled procedure is timeless).
- `Event` nodes are explicitly skipped.
- Add the new kinds to the constants near `_FINDING_KINDS`: a
  `_DISTILLED_NODE_KINDS = {"Runbook": "takeaway", "Gotcha": "insight"}` map; the
  matcher checks `node_type` against it before falling through to the existing
  `Session*` logic.

This makes the self-improvement loop weight reusable procedures and known
failure modes alongside raw session findings.

### 3. Loud-failure hint on empty findings
- `bin/harness_driver.py` `run_round`: when evidence is empty (the
  `status="skipped", detail="not enough evidence"` path), append to `detail`:
  `" — if a backend was rate-limited during compile it can cache empty
  extractions; run 'tesserae config status' to check provider liveness
  (Tesserae 0.9.0)."`
- Research loop: in the GROUND path (`orchestrator.ts`) or where
  `ingest.ts`/`synthesize.ts` report a missing/empty graph, emit the same
  one-line hint to stderr/detail. Non-fatal, informational only.

### 4. Enable distillation on GRD's compile + document it
- `lib/research/tesserae.ts`: add `--distill` to the compile args array. It is
  LLM-optional with a deterministic fallback and byte-idempotent, so it is
  offline-safe and won't change output determinism. (Decision flagged for
  review: on a sources-only ingest graph with no sessions, `--distill` is a
  near-no-op; included as a low-risk enabler + future-proofing. The alternative
  is to omit it and rely solely on the user's `tesserae refresh` distillation.)
- `retrieve.ts`: **no change** — node-type-agnostic ranking already surfaces
  distilled nodes; this is GRD's analog of `--multi-pool`.
- Docs: instruct users to set `distillation.enabled: true` in their Tesserae
  project config (or run refresh with distillation) so the **harness** graph
  gains `Runbook`/`Gotcha`.

### 5. Tests + docs
- `tests/python/test_harness_conformance.py` (new test class
  `TestRunbookEvidence`): build an in-memory `graph.json` with one `Session*`
  finding + one `Runbook` + one `Gotcha` + one `Event` node; assert
  `TesseraeFindings(repo).findings(None)` returns the Session finding, a
  `takeaway` Finding whose content starts `[runbook]`, and an `insight` Finding
  whose content starts `[gotcha]`, and does **not** include the `Event` node.
- `tests/python/test_harness_conformance.py`: assert the empty-evidence skip
  detail contains `tesserae config status`.
- `tests/unit/research/tesserae.test.ts`: extend the existing "compile invokes
  the real tesserae extractor with the right args" test (line 33) to also
  `expect(call).toContain('--distill')`.
- `CLAUDE.md`: under the Tesserae/autoresearch section, note that the harness
  now consumes AgentRunbook `Runbook`/`Gotcha` distilled memory, that users
  should enable `distillation.enabled` for the harness graph, and that
  `tesserae config status` diagnoses empty extraction.
- `docs/autoresearch-tutorial.md`: one short subsection mirroring the above.

## Data flow

```
user: tesserae sessions-import + tesserae refresh (distillation.enabled)
   → .tesserae/graph.json gains Session* findings + Runbook/Gotcha/Event nodes
harness: TesseraeFindings.findings()
   → Session* findings  +  Runbook→[runbook] takeaway  +  Gotcha→[gotcha] insight
   → select_evidence → evidence_md → proposer
research: retrieve.ts reads graph.json (all node types) → Runbook/Gotcha rank in
   grounding naturally; orchestrator GROUND builds the pack.
empty graph/findings anywhere → one-line "run tesserae config status" hint.
```

## Error handling
- Distilled nodes missing (distillation off / older graph): harness behaves
  exactly as today (filter simply matches nothing new). No hard dependency on
  0.9.0 — GRD degrades gracefully against an 0.8.x graph.
- Malformed/absent `graph.json`: unchanged existing handling (raises the same
  "run tesserae refresh first" `SystemExit` / returns no findings).
- `--distill` unsupported (older `tesserae` on PATH): compile would error on the
  unknown flag. Mitigation: the upgrade step (1) is a prerequisite; document the
  0.9.0 floor. (Implementation note: keep `--distill` last so a clear "unknown
  option" surfaces; do not silently swallow.)

## Testing strategy
Deterministic + offline: harness tests inject an in-memory graph dict; the TS
test injects a fake `run` capturing argv (existing pattern at
`tests/unit/research/tesserae.test.ts:33-45`). No live `tesserae` needed in CI;
the jest python wrapper skips when python3/autoresearch_core are unavailable.

## Risks
- **`--distill` cost/no-op on ingest graphs** — flagged decision; deterministic
  fallback + Tesserae's medium reasoning-effort cap bound the cost.
- **Kind remapping loses fidelity** — mitigated by the `[runbook]`/`[gotcha]`
  content prefix so provenance survives into `evidence_md` and audit records.
- **Version floor** — `--distill` and `config status` require 0.9.0; documented,
  and the consume-side degrades gracefully without them.

## Non-goals
- No `tesserae context`/`--multi-pool` call from GRD.
- No `Event`-node consumption or `precedes` traversal.
- No new `.planning/config.json` knobs (full-adoption option not selected).
