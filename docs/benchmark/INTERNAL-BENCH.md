# GRD internal benchmark (DRAFT)

30 self-contained tasks for measuring GRD against itself and against peer
agents (Aider, SWE-agent, OpenHands). Each task is reproducible from a
public git SHA + a `gd autopilot` invocation.

This file is intentionally a *spec*, not a leaderboard. The leaderboard
gets generated by running the tasks; results land in
`docs/benchmark/results/<DATE>-<AGENT>-<VERSION>.json`.

## Task taxonomy

| Bucket | Count | Difficulty | What it tests |
|---|---:|---|---|
| **refactor** | 8 | easy | rename / extract / inline across small modules |
| **bug-fix** | 8 | medium | reproduce from a failing test, fix, keep tests green |
| **feature-add** | 8 | medium | implement a documented feature behind a flag |
| **regression-hunt** | 4 | hard | bisect-style hunt for a regression in a known-good→known-bad range |
| **design-doc** | 2 | hard | produce a 1-page design with falsifiable predictions and at least one rejected alternative |

Total: 30 tasks.

## Scoring rubric

Each task scored 0 / 0.5 / 1:

- **1.0** — task complete; all tests pass; verdict has evidence; no
  regression elsewhere
- **0.5** — task partially complete; ≥1 test passes that didn't before;
  no regression
- **0.0** — task incomplete or regression

Composite = mean over the 30 tasks. Plus per-bucket means.

Two additional cross-cutting metrics:

- **falsification rate** — % of tasks where verifier verdict was
  `falsified` rather than `partial`. Higher = more honest.
- **wall-clock-per-task** — median wall clock per task. Lower = faster.

## Reproducibility

Each task ships as a small fixture repo under
`tests/benchmark/tasks/<task-id>/`. The harness:

1. Clones the fixture into a temp dir
2. Runs `gd init` (or competing agent's init)
3. Invokes `gd autopilot` (or competing agent's main loop) with a
   task-specific prompt from `tasks/<task-id>/prompt.md`
4. After completion, runs `tasks/<task-id>/verify.sh` which writes a
   verdict file
5. Aggregates verdicts into `docs/benchmark/results/<DATE>-<AGENT>-<VERSION>.json`

The harness lives at `scripts/run-internal-bench.mjs` (to be written
when tasks are populated).

## Why no SWE-bench yet?

SWE-bench measures _isolated_ patch generation: given an issue, produce
the diff. GRD's value proposition is the *closed loop with project
memory* — falsifiable reflections, DEAD-ENDS, drift, GENOME. A 30-task
internal benchmark that scores per-task **plus** the cross-cutting
honesty metric (falsification rate) measures the actual differentiator.

We'll also report SWE-bench Lite as a sanity score once the harness is
ready, but the internal bench is the primary scoreboard.
