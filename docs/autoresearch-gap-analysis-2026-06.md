# GRD Autoresearch Gap Analysis

**Date:** June 28, 2026
**Audience:** GRD maintainer
**Scope:** GRD (`gd`) + the version-locked `autoresearch-core` kernel, measured against the 2026 autoresearch / AI-R&D field.

---

## 1. Executive summary

GRD's central architectural bet — a **deterministic verdict (metric/comparator/target) with no LLM judge on the control path** — is now independently endorsed by the strongest 2026 results (HindSight, One-Token-to-Fool, the parallel-sampling ceiling, DGM removing its own hallucination markers, AIGS/POPPER falsification-first). The core loop, the cross-backend scheduler, and the eval-gated git-reversible life-harness are genuinely mature and well-tested. The confirmed gaps are not architectural holes but **hardening and lifecycle gaps**: experiment execution is unsandboxed by default with no reward-hacking tripwire, the self-improvement loop is a single linear chain with no variant lineage, and several "advertised" capabilities (semantic retrieval, distilled-memory freshness, citation integrity, reproducibility scoring) are thinner or more silently-degrading than the field's emerging standards. None of the ten verified gaps rose above **medium** impact, and every one has a small, high-leverage first step that stays on the deterministic side of GRD's design. The two medium-impact gaps (default sandboxing + tripwire; harness variant lineage) are the only ones meriting near-term work; the remaining eight are low-impact refinements to schedule opportunistically.

---

## 2. Where GRD is already strong vs the 2026 field

Grounded in the GRD and `autoresearch-core` capability maps:

- **Deterministic verdict / no LLM judge on the control path** (`lib/research/verdict.ts`, `autoresearch_core/verdict.py` + `policy.py`). Exactly the "verifiable rewards, rubrics only for style" split the field converged on (One-Token-to-Fool, RLVR, HindSight's novelty-negatively-correlates-with-impact result). The optional LLM eval report is gated and explicitly forbidden from overriding.
- **Falsification-first decision discipline** (`policy.py` `should_promote_dead_end`: only a *deterministic refutation* can auto-promote a dead end). Matches AIGS/Baby-AIGS and POPPER's "discovered only after surviving falsification."
- **Eval-gated, git-reversible self-improvement rounds** (`lib/commands/harness.ts` + `bin/harness_driver.py` binding `autoresearch_core` ports; npm lint/build:check/jest as the gate; review-mode default; kill_switch). The conservative, auditable take on the DGM / Karpathy-autoresearch / Sakana-RSI loop — and DGM's self-removed hallucination markers are direct evidence GRD is right to keep the verdict off the agent's editable surface.
- **Hardened (when enabled) sandbox** (`lib/research/docker-runner.ts`: `--network none`, `--cap-drop ALL`, `--read-only`, no-new-privileges, pids/mem/cpu caps, image-regex validation, path containment). The isolation primitives the reward-hacking literature (RHB, PostTrainBench, CTRL-ALT-DECEIT) demands — the only issue is that they are opt-in.
- **Typed KG grounding + hybrid retrieval** (`lib/research/{ingest,tesserae,retrieve}.ts`: RRF over lexical + semantic + graph-structure). The Agentic-GraphRAG industry pattern (≈62% hallucination reduction) and Kosmos's structured world model validate the KG-centric bet.
- **Read-only distilled memory** (Runbook→takeaway, Gotcha→insight; Event nodes skipped — `bin/harness_driver.py`). Consuming distilled memory *read-only as evidence* is precisely the mitigation the faulty-memory effect ("curated raw beats LLM consolidators") and TAME's "memory misevolution" argue for; EvoScientist/Memp validate the runbook/gotcha shape.
- **Multi-backend scheduler + account rotation + ultracode** (`lib/scheduler.ts`, `lib/ultracode.ts`). AdaptOrch and GEA's "backend/topology selection is the lever" thesis maps onto exactly this surface.
- **Self-monitoring trio** (drift score `lib/drift.ts`, DEAD-ENDS `lib/dead-ends.ts`, GENOME `lib/genome.ts`) — all deterministic, no-LLM-write, git-reversible — the persistent-world-model / AI-Supervisor frontier in conservative form.
- **Honest about its own dead ends**: `gd evolve` retired; two falsified self-improvement designs (Elo plan tournament, LLM meta-reviewer with write access) recorded — both rejected for reintroducing the LLM-judge/LLM-write anti-pattern.

## 5. High-impact gaps (detailed)

No verified gap rose above **medium** impact — a healthy signal that the architecture is sound. The two medium-impact gaps below are the highest-priority tier and the only ones meriting near-term work; both stay strictly on the deterministic side of GRD's design.

### Gap 1 — Default-unsandboxed execution + no reward-hacking tripwire (medium / low effort)

**Current GRD state.** `docker-runner.ts:78` selects `mode: raw.research_sandbox === 'docker' ? 'docker' : 'subprocess'`. Only the literal `'docker'` enables the hardened container; unset → the default `createSubprocessRunner` in `runner.ts` runs the generated script via `execFileSync(bin,[scriptFile],{cwd:threadDir})` with the host's full network and filesystem and no path containment (the `resolveContained` guard exists only in the docker path). The loud "running UNSANDBOXED on host" warning (`docker-runner.ts:194–197`) fires *only* when docker is explicitly requested but the binary is missing — never on the default. Separately, the deterministic verdict is computed purely from `__RESULT__`, and nothing watches for the exploits the 2026 reward-hacking literature treats as standard (train-on-test, checkpoint download, network egress, grader/metric tampering, found-key misuse) — so a correct-looking `__RESULT__` from a cheated run promotes to KNOWHOW.md, and `gd harness round` shares the same exposure surface.

**What to add.** (a) An `auto` sandbox mode that prefers docker when a usable binary is present and emits a one-line warning whenever it falls back to subprocess, so *degrade is visible*; keep current behavior for explicit `'subprocess'`. (b) A cheap, deterministic, advisory tripwire that flags experiments which open network sockets or write outside `threadDir`, recorded alongside the verdict but **never overriding it** (the verdict stays authoritative — this is telemetry, matching CTRL-ALT-DECEIT's warning that a single LLM monitor is insufficient).

**Minimal first step.** In `lib/research/docker-runner.ts`: probe once for a usable `docker` binary and treat `research_sandbox` unset/`'auto'` as docker-when-available; print the existing fallback warning on the default path too. No new dependency, ~15 lines. (The tripwire is a small follow-up; ship `auto` first.)

**Over-engineering to avoid.** Do **not** build a syscall-level sandbox, eBPF egress monitor, or an LLM-based "cheat detector" — those reintroduce a non-deterministic judge and heavy deps for a single-process harness. A docker-when-available default plus a grep-for-socket/path-write advisory flag captures the bulk of the value at near-zero cost.

### Gap 2 — Linear harness self-improvement; no variant lineage/archive (medium / medium effort)

**Current GRD state.** Rounds form a single chain on HEAD. `autoresearch_core/types.py` `RoundRecord` (~L143) carries `applied_sha` but no `parent_sha`/`base_sha`; `rounds.py` `decide_round` decides one candidate; `bin/harness_driver.py` `run_round` always branches the scratch worktree from current HEAD and merges back onto HEAD; the applied/eval-rejected patch-hash dedupe set (`hashes.jsonl`) *permanently* blocks re-proposing a rejected variant — the exact inverse of DGM's "weak ancestors seed later breakthroughs." Per-round audit files exist under `.planning/harness/rounds/<id>/` (`gd harness status`), but with no parent links and no select-a-parent step, so the DGM-sense archive is absent. (The autoresearch *hypothesis* loop does carry lineage via `Hypothesis.parent_id` + `decide_branch→revise`, but that is a separate subsystem.)

**What to add.** A lineage field plus a parent-selection policy so a later round can base its worktree on a non-HEAD ancestor (a promising-but-rejected stepping stone). Keep eval-gating and git-revert exactly as-is; this is data + a selection rule, not a new loop or an editable meta-level.

**Minimal first step.** Add `parent_sha: str | None = None` to `RoundRecord` in `autoresearch_core/types.py`, and have `bin/harness_driver.py` write the prior `applied_sha` into it. A pure data change (no behavior shift) that unblocks archive/lineage features later. A natural small follow-up: stop *permanently* blocking eval-rejected hashes (vs applied-rejected) so a stepping-stone can be revisited from a different parent.

**Over-engineering to avoid.** Do **not** adopt DGM/Hyperagents open-ended *population* search or an editable meta-loop ("improve the improver"). Removing GRD's hardcoded task/meta alignment is the precise failure surface the eval gates + git-reversibility + kill_switch exist to contain — and GRD already falsified the LLM-meta-reviewer design. Lineage *data* is cheap and safe; population evolution is not.

## 6. Explicitly NOT recommended

Field trends GRD should deliberately skip, with the reason:

- **LLM judges / agent-as-judge / rubric verifiers on the control path** (PaperBench's LLM-judge rubric, DeepVerifier, CoEvoSkills' surrogate verifier replacing ground truth). One-Token-to-Fool (≈35% false positives from a lone `:`), the IRT reliability study, and HindSight's novelty↔impact anti-correlation all confirm this is GRD's core anti-pattern. An *off-path, optional* commentary layer is fine; never on the verdict.
- **Free-form LLM rewrite/consolidation of memory in-place** (aggressive distillation/compaction of the Tesserae KG). The faulty-memory effect (100%→52.6% over 10 consolidation rounds; curated raw beats consolidators) and TAME's memory-misevolution make this actively harmful. Keep distilled memory read-only; do curation + deprecation (Gap 6), not rewrite.
- **Editable meta-loop / metacognitive self-modification** (DGM-Hyperagents "improve the improver", DARWIN dynamic self-rewriting network). It dissolves the eval-gate/kill-switch boundary GRD relies on; adopt lineage *data* (Gap 2) instead.
- **Learned RL stop/allocate policy for the portfolio** (full ATLAS-style controller). Over-engineering for GRD's small default portfolios (maxCandidates 3, concurrency 2); a static `stopOnFirstSupported` flag (Gap 5) captures the win.
- **Per-mode learned retrieval router with a trained classifier** beyond the trivial heuristic — RRF already blends everything and is unweighted; gains are incremental (Gap 10 is itself flagged marginal).
- **BH/FDR implemented literally over the deterministic verdicts**, or adding a stats kernel to `autoresearch_core/policy.py` (deliberately zero-dependency, zero-statistics). There is no per-candidate p-value to correct; if anything is done, reuse the existing TS `benjaminiHochberg()` in `lib/commands/patterns.ts` as a presentational `fdr_flag` only.
- **Physical/wet-lab "AI Science Factories" and managed-cloud discovery platforms** (Periodic Labs, Lila, FutureHouse Robin, Microsoft Discovery, Virtual Lab, Biomni). Out of scope for a local CLI/plugin harness; the robotic/wet-lab reward loop is a different product category.
- **AI-as-sole-author / AI-only peer-review publication pipelines** (Agents4Science, Zochi, Carl). GRD's paper path should produce *checkable, citation-verified* artifacts (Gap 7), not chase author/reviewer-automation norms that are themselves contested and integrity-flagged.
