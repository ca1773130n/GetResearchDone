    Add the following functions to lib/discussion.ts and export them from the module.exports block:

    **1. runPrePlanningDiscussion(options)** — REQ-138
    - Signature: `function runPrePlanningDiscussion(options: { phaseGoal: string; requirements: string[]; cwd?: string; phase?: string; milestone?: string | null; config: GrdConfig }): Promise<DiscussionResult | null>`
    - Check `config.discussion?.before_planning !== false` AND `config.discussion?.enabled !== false` AND `config.backend_roles?.brainstormer` is set
    - If any check fails, return null (silently skip)
    - Detect available backends; if brainstormer backend unavailable, return null
    - Build a topic string: "Pre-planning discussion for phase goal: {phaseGoal}\n\nRequirements:\n- {req1}\n- {req2}..."
    - Call `runDiscussion(topic, [brainstormerBackend], { rounds: 1, phase, type: 'pre-planning', cwd, milestone })`
    - Return the DiscussionResult

    **2. runPreExecutionDiscussion(options)** — REQ-139
    - Signature: `function runPreExecutionDiscussion(options: { planSummary: string; cwd?: string; phase?: string; milestone?: string | null; config: GrdConfig }): Promise<DiscussionResult | null>`
    - Check `config.discussion?.before_execution === true` AND `config.discussion?.enabled !== false` AND `config.backend_roles?.brainstormer` is set
    - If any check fails, return null
    - Single round discussion with brainstormer about implementation concerns
    - Topic: "Pre-execution discussion: surface implementation concerns for the following plan:\n\n{planSummary}"
    - Call `runDiscussion(topic, [brainstormerBackend], { rounds: 1, phase, type: 'pre-execution', cwd, milestone })`

    **3. reviewPlanViaBackend(options)** — REQ-140
    - Signature: `function reviewPlanViaBackend(options: { planText: string; cwd?: string; config: GrdConfig }): PlanReviewResult | null`
    - Check `config.backend_roles?.reviewer` is set and reviewer is not the primary backend (from `config.backend`)
    - If check fails, return null
    - Detect available backends; if reviewer unavailable, return null
    - Build prompt asking reviewer to evaluate the plan and respond in a structured format: "Review the following plan...\nRespond with JSON: { approved: boolean, concerns: [{description, severity}], suggestions: [string] }"
    - Call `dispatchToBackend(reviewerBackend, prompt, { cwd })`
    - Parse the JSON from the response (extract JSON from markdown code fences if present); if parsing fails, return a result with `approved: false`, one concern with severity 'warning' and description about unparseable response, and the raw text as a suggestion
    - Return PlanReviewResult

    **4. reviewCodeViaBackend(options)** — REQ-141
    - Signature: `function reviewCodeViaBackend(options: { diff: string; cwd?: string; config: GrdConfig }): CodeReviewResult | null`
    - Same reviewer availability checks as reviewPlanViaBackend
    - Build prompt asking for structured code review: "Review this code diff...\nRespond with JSON: { approved: boolean, issues: [{severity, file, line_range, description}], summary: string }"
    - Parse JSON response; handle parse failures gracefully
    - Return CodeReviewResult

    **5. reviewPRViaBackend(options)** — REQ-142
    - Signature: `function reviewPRViaBackend(options: { diff: string; prNumber: number; cwd?: string; config: GrdConfig }): PRReviewResult | null`
    - Check `config.code_review_enabled` AND `config.backend_roles?.reviewer` is set
    - Build prompt asking for PR-level review comments: "Review this PR diff...\nRespond with JSON: { comments: [{file, line, body, severity}], summary: string }"
    - Parse JSON response; handle parse failures
    - Return PRReviewResult

    **Shared helper (internal, not exported):**
    - `parseJSONFromResponse(raw: string): Record<string, unknown> | null` — Extracts JSON from raw response text, handling markdown code fences (```json ... ```) and plain JSON. Returns null on parse failure.
