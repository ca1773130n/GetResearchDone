    Create `lib/wireup/report.ts` for report generation:

    1. **Define the report data type:**
       ```typescript
       interface WireupReportData {
         milestone: string;
         iteration: number;
         timestamp: string;
         features_tested: number;
         scenarios: {
           total: number;
           passed: number;
           failed: number;
           skipped: number;
         };
         issues_found: MissingConnection[];
         fixes: {
           applied: FixAttempt[];
           verified: number;
           failed: number;
           skipped: number;
         };
         remaining_unwired: string[];
         manual_review: MissingConnection[];
       }
       ```

    2. **`generateWireupReport(cwd, reportData)` function:**
       - **Resolve output path:** Use `lib/paths.ts` to get the milestone directory, then construct `.planning/milestones/{milestone}/wireup/WIREUP-REPORT.md`. Create the wireup directory if it does not exist (`fs.mkdirSync` with `{ recursive: true }`).
       - **Build the report markdown** with these sections:

         ```markdown
         # Wireup Report

         **Milestone:** {milestone}
         **Iteration:** {iteration}
         **Generated:** {timestamp}

         ## Summary

         | Metric | Count |
         |--------|-------|
         | Features Tested | {N} |
         | Scenarios Run | {N} |
         | Scenarios Passed | {N} |
         | Scenarios Failed | {N} |
         | Scenarios Skipped | {N} |
         | Issues Found | {N} |
         | Fixes Applied | {N} |
         | Fixes Verified | {N} |
         | Fixes Failed | {N} |
         | Remaining Unwired | {N} |

         ## Issues Found

         | # | Type | Source | Target | Confidence | Fix Status |
         |---|------|--------|--------|------------|------------|
         (one row per issue)

         ## Fixes Applied

         | # | Issue Type | Description | Status | Re-run Passed |
         |---|------------|-------------|--------|---------------|
         (one row per fix attempt)

         ## Requires Manual Review

         (for each medium/low confidence issue:)
         ### {issue_type}: {source_file} -> {target_file}
         **Confidence:** {confidence}
         **Suggested Fix:** {suggested_fix}

         ## Remaining Unwired Features

         - {feature_1}
         - {feature_2}
         ...
         ```

       - **Append iteration history:** Read the existing WIREUP-REPORT.md if it exists. Extract the `## Iteration History` section if present. Append a new row to the history table:

         ```markdown
         ## Iteration History

         | Iteration | Date | Scenarios | Passed | Failed | Skipped | Issues | Fixes | Verified |
         |-----------|------|-----------|--------|--------|---------|--------|-------|----------|
         (append new row with current iteration data)
         ```

         If the report file already exists, preserve the existing iteration history rows and append the new one. If the file does not exist, create the history table with just the current row.

       - **Write the report:** Overwrite the main report sections (Summary through Remaining Unwired) but preserve and append to the Iteration History section. Use `fs.writeFileSync` to write the complete file.

    3. **`extractIterationHistory(existingContent: string): string` helper:**
       - Parse existing WIREUP-REPORT.md content
       - Find the `## Iteration History` section
       - Extract and return just the table rows (excluding the header row)
       - Return empty string if no history section exists

    4. **`formatReportPath(cwd: string): string` helper:**
       - Use `currentMilestone(cwd)` from `lib/paths.ts` to resolve the milestone
       - Return `path.join(cwd, '.planning', 'milestones', milestone, 'wireup', 'WIREUP-REPORT.md')`

    5. Export `generateWireupReport`, `formatReportPath`, `extractIterationHistory`, and `WireupReportData` type from the module.
