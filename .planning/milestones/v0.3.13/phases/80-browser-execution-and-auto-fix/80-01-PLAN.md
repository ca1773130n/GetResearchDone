<task type="auto">
  <name>Task 2: Implement executeBrowserScenario() with playwright_available guard in lib/wireup/execution.ts</name>
  <files>lib/wireup/execution.ts, lib/wireup/types.ts, lib/wireup/index.ts</files>
  <action>
    Add browser scenario execution to `lib/wireup/execution.ts` with the following structures and functions:

    1. **Define types** (add to `lib/wireup/types.ts` alongside existing wireup types):

       ```typescript
       interface BrowserStep {
         action: 'navigate' | 'fill' | 'click' | 'snapshot' | 'evaluate';
         selector?: string;
         value?: string;
         url?: string;
         script?: string;
         expected?: Record<string, unknown>;
       }

       interface BrowserScenarioResult {
         scenario_id: string;
         feature: string;
         status: 'passed' | 'failed' | 'skipped';
         skip_reason?: string;
         manual_steps?: string[];
         steps: BrowserStepResult[];
         console_errors: string[];
       }

       interface BrowserStepResult {
         action: string;
         status: 'passed' | 'failed' | 'skipped';
         error?: string;
         dom_snapshot?: string;
       }
       ```

    2. **`executeBrowserScenario(cwd, scenario, playwrightAvailable)` function:**

       - **When `playwrightAvailable` is false:**
         - Return a `BrowserScenarioResult` with `status: 'skipped'`
         - Set `skip_reason: 'Playwright MCP tools not available. Install @anthropic/mcp-playwright or configure playwright.enabled in .planning/config.json'`
         - Generate `manual_steps` array from the scenario steps — e.g., for a navigate step: `'Open browser to <url>'`, for a fill step: `'Enter "<value>" in <selector>'`, for a click step: `'Click on <selector>'`
         - Return immediately (no browser interaction attempted)

       - **When `playwrightAvailable` is true:**
         - Iterate through scenario steps in order
         - For each step, construct the appropriate Playwright MCP tool call payload:
           - `navigate` -> `{ tool: 'browser_navigate', params: { url } }`
           - `fill` -> `{ tool: 'browser_fill_form', params: { selector, value } }`
           - `click` -> `{ tool: 'browser_click', params: { selector } }`
           - `snapshot` -> `{ tool: 'browser_snapshot', params: {} }`
           - `evaluate` -> `{ tool: 'browser_evaluate', params: { script } }`
         - **Important:** The actual MCP tool invocation is delegated to the calling agent context (wireup orchestrator). This function builds the structured step plan and expected outcomes. It does NOT spawn subprocesses or call MCP tools directly — it produces an execution plan that the wireup agent interprets.
         - Record each step result (passed/failed) with any error message
         - After all steps, collect console errors from evaluate steps that checked `window.console` state
         - Return the full `BrowserScenarioResult`

    3. **`generateManualSteps(steps: BrowserStep[]): string[]` helper:**
       - Convert browser steps to human-readable manual testing instructions
       - Each step becomes a numbered instruction: `'1. Navigate to http://...'`, `'2. Enter "test" in the search field'`, etc.

    4. Export `executeBrowserScenario`, `generateManualSteps`, and all new types from the module.

    5. **Update `lib/wireup/index.ts`:** Add re-exports for `executeBrowserScenario` and `generateManualSteps` from `./execution`, and re-export the new types from `./types`.

    Use typed require for detectPlaywright (note `../backend` path since execution.ts is inside `lib/wireup/`):
    ```typescript
    const { detectPlaywright }: { detectPlaywright: (cwd: string) => PlaywrightResult } = require('../backend');
    ```
