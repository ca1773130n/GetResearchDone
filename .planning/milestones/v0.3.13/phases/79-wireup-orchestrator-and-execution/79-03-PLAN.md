<task type="auto">
  <name>Task 1: Define MissingConnection type and implement detection heuristics</name>
  <files>lib/wireup/types.ts, lib/wireup/detection.ts</files>
  <action>
    First, add to `lib/wireup/types.ts`:

    ```typescript
    type IssueType =
      | 'missing-route'
      | 'unconnected-handler'
      | 'missing-import'
      | 'missing-middleware'
      | 'broken-nav-link'
      | 'missing-env-var';

    type Confidence = 'high' | 'medium' | 'low';

    interface MissingConnection {
      issue_type: IssueType;
      source_file: string;
      target_file: string;
      suggested_fix: string;
      confidence: Confidence;
      scenario_id: string;
      step_index: number;
      error_context: string;
    }
    ```

    Then create `lib/wireup/detection.ts`:

    1. `detectMissingConnections(cwd: string, failedResults: ScenarioResult[]): MissingConnection[]`
       - Filter to only failed scenarios (overall_passed === false)
       - For each failed step in each scenario, apply classification heuristics
       - Return deduplicated MissingConnection[] sorted by confidence (high first)

    2. Classification heuristics (all filesystem-based, no LLM calls):

       **missing-route** (high confidence):
       - HTTP step failed with 404 status code
       - Grep cwd for route registration patterns matching the URL path (e.g., `app.get`, `router.post`, `@Get`, `@Post`)
       - If URL path not found in any route file: issue_type='missing-route', source_file=scenario feature file, target_file=likely router file (search for `router` or `routes` in filenames)
       - suggested_fix: "Register route {METHOD} {PATH} in {target_file}"

       **unconnected-handler** (medium confidence):
       - HTTP step returned 200 but body does not match expected (empty response, default response)
       - Search for handler function matching the route but with placeholder/TODO body
       - suggested_fix: "Connect handler logic in {target_file} for route {PATH}"

       **missing-import** (high confidence):
       - CLI step failed with exit code indicating module not found (stderr contains "Cannot find module", "ModuleNotFoundError", "ImportError")
       - Parse the module name from the error
       - source_file: the file that tried to import, target_file: the missing module path
       - suggested_fix: "Add import for {module} in {source_file} or create {target_file}"

       **missing-middleware** (medium confidence):
       - HTTP step returned 401/403 status
       - Search for auth middleware registration in cwd
       - suggested_fix: "Register authentication middleware for route {PATH}"

       **broken-nav-link** (low confidence):
       - HTTP step returned 404 for a path that looks like a page route (not API)
       - Search for navigation/link references to this path in frontend files
       - suggested_fix: "Add page route for {PATH} or fix navigation link in {source_file}"

       **missing-env-var** (high confidence):
       - CLI or HTTP step error contains "undefined" for known env var patterns, or stderr contains "ECONNREFUSED" to a service URL typically configured via env
       - Search for process.env references in relevant files
       - suggested_fix: "Set environment variable {VAR_NAME} or add to .env"

    3. `classifyFailure(cwd: string, step: StepResult, scenario: WireupScenario): MissingConnection | null`
       - Dispatcher function that runs each heuristic in order and returns the first match
       - Returns null if no heuristic matches (unclassifiable failure)

    4. Helper functions (internal, not exported):
       - `grepForPattern(cwd: string, pattern: string, globs?: string[]): string[]` — uses child_process.spawnSync with `grep -r` or Node fs.readFileSync scanning to find pattern matches. Use spawnSync with execFileSync for safety (no shell injection).
       - `findRouteFiles(cwd: string): string[]` — heuristic to locate route/controller files
       - `parseModuleFromError(stderr: string): string | null` — extract module name from error message

    Follow code style: 'use strict', CommonJS, typed destructuring, no `any`, pure filesystem analysis.
