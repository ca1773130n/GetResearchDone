<task type="auto">
  <name>Task 1: Define execution-related types and implement HTTP/CLI step execution</name>
  <files>lib/wireup/types.ts, lib/wireup/execution.ts</files>
  <action>
    First, extend `lib/wireup/types.ts` with execution types (add to existing types from Phase 78):

    ```typescript
    interface StepResult {
      step_index: number;
      step_type: 'http' | 'cli';
      passed: boolean;
      expected: unknown;
      actual: unknown;
      error?: string;
      duration_ms: number;
    }

    interface HttpStepResult extends StepResult {
      step_type: 'http';
      status_code: number;
      headers: Record<string, string>;
      body: string;
    }

    interface CliStepResult extends StepResult {
      step_type: 'cli';
      exit_code: number;
      stdout: string;
      stderr: string;
    }

    interface ScenarioResult {
      scenario_id: string;
      feature_id: string;
      step_results: StepResult[];
      overall_passed: boolean;
      duration_ms: number;
    }

    interface ExecutionOptions {
      timeout_ms?: number;
      base_url?: string;
    }
    ```

    Then create `lib/wireup/execution.ts`:

    1. `executeHttpStep(step: WireupScenarioStep, options: ExecutionOptions): Promise<HttpStepResult>`
       - Use Node.js built-in `fetch()` (available in Node 18+) to make HTTP requests
       - Capture: response.status, response.headers (convert to plain object), response body (as text)
       - Compare status code against step.expected_outcome.status if present
       - Compare body against step.expected_outcome.body_contains if present (substring match)
       - Compare headers against step.expected_outcome.headers if present
       - Set passed = true only if ALL expected comparisons match
       - Wrap in try/catch: network errors (ECONNREFUSED, timeout) produce a failed result with error message, not an exception
       - Record duration_ms using Date.now() or performance.now()

    2. `executeCliStep(step: WireupScenarioStep, options: ExecutionOptions): Promise<CliStepResult>`
       - Use child_process.spawnSync to run the CLI command (NOT exec — use spawnSync/execFileSync for safety, avoiding shell injection)
       - Parse step.parameters.command and step.parameters.args
       - Capture: stdout (utf-8 string), stderr (utf-8 string), exit code (status property)
       - Compare exit_code against step.expected_outcome.exit_code if present
       - Compare stdout against step.expected_outcome.stdout_contains if present (substring match)
       - Compare stderr against step.expected_outcome.stderr_contains if present (substring match)
       - Set passed = true only if ALL expected comparisons match
       - Set timeout from options.timeout_ms (default 30000ms)
       - Wrap in try/catch: spawn errors produce a failed result with error message

    3. `executeScenarios(cwd: string, scenarios: WireupScenario[], options?: ExecutionOptions): Promise<ScenarioResult[]>`
       - Iterate through scenarios sequentially (not parallel — avoid overwhelming localhost)
       - For each scenario, iterate through its steps array
       - Dispatch each step to executeHttpStep or executeCliStep based on step.step_type
       - Skip 'browser' and 'assert' step types (those are Phase 80) — mark as skipped in results
       - Compute overall_passed = all step_results have passed === true
       - Return ScenarioResult[] array

    Follow code style: 'use strict', CommonJS require with typed destructuring, zero external deps (Node built-ins only), prefix unused args with `_`.
  </action>
