Create the wireup type system and discovery engine that identifies unwired features via pure filesystem analysis.

Purpose: The discovery engine is the foundation of the wireup command — it scans the codebase for features that exist but lack full integration (exported-but-uncalled functions, config options without CLI surface, API endpoints without integration tests). This enables the wireup orchestrator (Phase 79) to generate targeted scenarios.
Output: `lib/wireup/types.ts` with all wireup domain types, `lib/wireup/discovery.ts` with `discoverUnwiredFeatures()`, and comprehensive unit tests.

    3. **ScenarioStepType** — string union: `'http' | 'cli' | 'browser' | 'assert'`

    4. **ScenarioStep** — interface with fields:
       - `step_type: ScenarioStepType`
       - `parameters: Record<string, unknown>` (step-specific params)
       - `expected_outcome: string`

    5. **WireupScenario** — interface with fields:
       - `feature: UnwiredFeature` (the feature being tested)
       - `steps: ScenarioStep[]`
       - `test_data_fixture: string` (path to generated fixture file)

    6. **WireupIterationHistory** — interface with fields:
       - `iteration: number`
       - `timestamp: string`
       - `scenarios_run: number`
       - `passed: number`
       - `failed: number`
       - `fixes_applied: number`

    7. **WireupState** — interface with fields:
       - `features_discovered: number`
       - `scenarios_generated: number`
       - `scenarios_passed: number`
       - `scenarios_failed: number`
       - `fixes_applied: number`
       - `iteration_history: WireupIterationHistory[]`

<task type="auto">
  <name>Task 2: Implement discoverUnwiredFeatures() with filesystem analysis</name>
  <files>lib/wireup/discovery.ts, tests/unit/wireup-discovery.test.ts</files>
  <action>
    Create `lib/wireup/discovery.ts` following `lib/evolve/discovery.ts` patterns:
    - `'use strict'` at top, JSDoc module header with `@dependencies ./types, ../utils, ../paths`
    - Import `UnwiredFeature`, `UnwiredFeatureCategory` from `./types`
    - Import `safeReadFile` from `../utils` using typed require pattern
    - Import `path` and `fs` from Node built-ins
    - Use `const { ... } = require(...)` with inline type annotations (typed require pattern from CONVENTIONS.md)

    Implement three private scanner functions and one public orchestrator:

    **1. `scanExportedButUncalled(cwd: string): UnwiredFeature[]`**
    - Read all `lib/*.ts` files (use `fs.readdirSync`)
    - For each file, extract exported function names via regex: `module\.exports\s*=\s*\{([^}]+)\}` or `exports\.\w+`
    - Build a set of all exported names
    - For each exported name, search across `lib/`, `bin/`, `commands/` for references (grep-like: read files and check for the function name string)
    - If an export appears in no file other than its own definition, it is "exported-but-uncalled"
    - Return `UnwiredFeature[]` with `category: 'exported-but-uncalled'`, relative `filePath`, `functionName`, and `suggestedAction: 'Add call site in a command, route, or test'`

    **2. `scanConfigWithoutSurface(cwd: string): UnwiredFeature[]`**
    - Read `.planning/config.json` to extract all top-level config keys
    - Search `commands/*.md` and `bin/*.ts` for references to each config key
    - Config keys not referenced in any command or binary are "config-without-surface"
    - Return `UnwiredFeature[]` with `category: 'config-without-surface'`, `filePath: '.planning/config.json'`, `functionName` = the config key, `suggestedAction: 'Expose via CLI flag, command option, or settings UI'`

    **3. `scanEndpointsWithoutTests(cwd: string): UnwiredFeature[]`**
    - Scan `lib/mcp-server.ts` for registered tool/endpoint names (look for patterns like tool name strings in the MCP registration)
    - Check `tests/integration/` for references to each endpoint name
    - Endpoints without integration test references are "endpoint-without-integration-test"
    - Return `UnwiredFeature[]` with `category: 'endpoint-without-integration-test'`, appropriate `filePath`, `functionName`, and `suggestedAction: 'Add integration test covering this endpoint'`

    **4. `discoverUnwiredFeatures(cwd: string): UnwiredFeature[]`** (public, exported)
    - Call all three scanners, concatenate results, return sorted by category then filePath
    - MUST NOT spawn any child processes — pure `fs.readFileSync` / `fs.readdirSync` only

    **Unit tests** in `tests/unit/wireup-discovery.test.ts`:
    - Use `jest.mock` to mock `fs` and `../utils` for controlled testing
    - Test each scanner returns correct category and structure
    - Test the main function returns combined results sorted correctly
    - Test edge case: empty codebase returns empty array
    - Test edge case: malformed files are skipped gracefully (no throw)
    - Follow existing test patterns from `tests/unit/` (describe/it blocks, expect assertions)
    - Target: at least 8 test cases

    **module.exports** at bottom of discovery.ts:
    ```
    module.exports = { discoverUnwiredFeatures };
    ```
    Keep scanner functions private (not exported).
