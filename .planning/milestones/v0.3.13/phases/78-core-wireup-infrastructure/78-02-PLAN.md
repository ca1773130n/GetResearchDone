<task type="auto">
  <name>Task 1: Implement scenario generation from unwired features</name>
  <files>lib/wireup/scenarios.ts</files>
  <action>
    Create `lib/wireup/scenarios.ts` following established lib/ module patterns:
    - `'use strict'` at top, JSDoc module header with `@dependencies ./types, ../utils, ../paths`
    - Typed require imports for `fs`, `path`, `safeReadFile` from `../utils`, path helpers from `../paths`
    - Import types from `./types`

    **1. `generateScenarios(features: UnwiredFeature[], cwd: string): WireupScenario[]`** (public)
    - For each UnwiredFeature, generate a WireupScenario with appropriate steps based on category:

    For `'exported-but-uncalled'`:
      - Step 1: `{ step_type: 'cli', parameters: { command: 'node', args: [...] }, expected_outcome: 'Function executes without error' }`
      - Step 2: `{ step_type: 'assert', parameters: { check: 'return_value_defined' }, expected_outcome: 'Function returns a non-undefined value' }`

    For `'config-without-surface'`:
      - Step 1: `{ step_type: 'cli', parameters: { command: 'gd', args: ['settings'] }, expected_outcome: 'Config key appears in settings output' }`
      - Step 2: `{ step_type: 'assert', parameters: { check: 'config_key_visible', key: feature.functionName }, expected_outcome: 'Config option is accessible via CLI' }`

    For `'endpoint-without-integration-test'`:
      - Step 1: `{ step_type: 'http', parameters: { method: 'POST', endpoint: feature.functionName }, expected_outcome: 'Endpoint responds with valid JSON' }`
      - Step 2: `{ step_type: 'assert', parameters: { check: 'response_schema_valid' }, expected_outcome: 'Response matches expected schema' }`

    - Set `test_data_fixture` to the path where `generateTestData` will write the fixture: `.planning/milestones/{milestone}/wireup/test-data/{feature.functionName}.json`
    - Use `currentMilestone(cwd)` from `lib/paths.ts` to resolve the milestone

    **2. `generateTestData(scenarios: WireupScenario[], cwd: string): void`** (public)
    - For each scenario, analyze the feature's source file to derive realistic test payloads:
      - Read the source file at `feature.filePath`
      - Extract function signature parameters via regex (e.g., `function name(param1: Type1, param2: Type2)`)
      - Generate a fixture object with sensible defaults for each parameter type:
        - `string` -> `"test-value"`
        - `number` -> `42`
        - `boolean` -> `true`
        - `string[]` -> `["item-1", "item-2"]`
        - `Record<string, unknown>` or object -> `{ "key": "value" }`
        - Unknown -> `null`
    - Write each fixture as JSON to the path specified in `scenario.test_data_fixture`
    - Create parent directories with `fs.mkdirSync({ recursive: true })`
    - Each fixture file contains: `{ "feature": feature.functionName, "parameters": { ... }, "generated_at": ISO timestamp }`

    **module.exports:**
    ```
    module.exports = { generateScenarios, generateTestData };
    ```

    npm run build:check (Level 1: Sanity — TypeScript compiles)
  </verify>
  <done>
    generateScenarios() produces valid WireupScenario[] for all three feature categories,
    generateTestData() writes JSON fixtures with realistic payloads to the wireup test-data directory
  </done>
