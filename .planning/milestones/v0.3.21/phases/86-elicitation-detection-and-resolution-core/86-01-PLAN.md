<task type="auto">
  <name>Task 1: Define ElicitationDetection type and implement detectElicitation()</name>
  <files>lib/types.ts, lib/discussion.ts</files>
  <action>
    1. In `lib/types.ts`, add the `ElicitationDetection` interface after the existing `DiscussionRoundEntry` type:

    ```typescript
    export interface ElicitationDetection {
      /** The extracted question text */
      question: string;
      /** Which detection patterns matched (for debugging/logging) */
      patterns: string[];
      /** Confidence: 'high' for direct questions, 'medium' for heuristic matches */
      confidence: 'high' | 'medium';
    }
    ```

    2. In `lib/discussion.ts`, add `ElicitationDetection` to the import type list from `./types`.

    3. Implement `detectElicitation(output: string): ElicitationDetection | null` in `lib/discussion.ts`:
       - Parse `output` line-by-line
       - Skip lines that are inside code blocks (track ``` fences)
       - Skip lines that start with `//`, `*`, `#` (comments, markdown headers)
       - Skip lines where `?` appears inside quoted strings (simple heuristic: odd number of quotes before `?`)
       - Detection patterns (in priority order):
         a. **Direct question**: Line ends with `?` (after trimming) and is not in a code/comment context -> confidence: 'high'
         b. **Numbered options**: 2+ consecutive lines matching `/^\s*\d+[\.\)]\s+/` -> confidence: 'high'
         c. **Clarification phrases**: Line contains "Please clarify", "Which approach", "Could you specify", "Would you prefer", "Do you want" (case-insensitive) -> confidence: 'high'
         d. **Option prompt**: Line contains "Choose one", "Select an option", "Pick one" -> confidence: 'medium'
       - Return the first match found, with `question` being the matched line(s) and `patterns` listing which pattern(s) triggered
       - Return `null` if no elicitation detected

    4. Add `detectElicitation` to the `module.exports` object at the bottom of `lib/discussion.ts`.

    Important: The function must handle multi-line input (full subprocess stdout). Extract the question text cleanly — strip leading/trailing whitespace, combine multi-line questions (numbered options get joined with newlines).

    Avoid: Do not use complex NLP or AST parsing. Simple regex-based line-by-line parsing is sufficient and maintainable. Do not match questions that appear in error messages or stack traces (lines starting with "at ", "Error:", "Warning:").
  </action>
