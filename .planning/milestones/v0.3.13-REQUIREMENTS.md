# Requirements: v0.3.13 Wireup Command

**Milestone:** v0.3.13
**Created:** 2026-03-20

## Core Command

### REQ-120: /grd:wireup Slash Command
**Priority:** P1 — High
**Category:** Command
**Description:** Register `/grd:wireup` as a GRD slash command. The command orchestrates a wireup iteration: discover unwired features -> generate usage scenarios -> execute scenarios -> detect failures -> fix issues -> report results. Similar structure to `/grd:evolve` but focused on integration wiring rather than feature discovery. Accepts optional `--target <feature>` to focus on a specific feature area.

### REQ-121: Wireup Discovery Engine
**Priority:** P1 — High
**Category:** Core
**Description:** Implement `discoverUnwiredFeatures()` in a new `lib/wireup.ts` module. Scans codebase for features that exist but lack full wiring: exported functions not called from any command/route, UI components not reachable from navigation, API endpoints without integration tests, event handlers without triggers, config options without UI or CLI surface. Uses pure filesystem analysis (no LLM calls), similar to evolve's discovery engine. Returns structured list of unwired features with category, location, and suggested wiring action.

### REQ-122: Usage Scenario Generation
**Priority:** P1 — High
**Category:** Core
**Description:** Generate concrete usage scenarios for each unwired feature. A scenario is a sequence of steps that exercises a feature end-to-end: "create test data -> call endpoint -> verify response -> check side effects". Scenarios are written as structured JSON with step type (http, cli, browser, assert), parameters, and expected outcomes. The agent generates scenarios using codebase analysis — reading route definitions, component props, CLI command signatures.

### REQ-123: HTTP/CLI Scenario Execution
**Priority:** P1 — High
**Category:** Execution
**Description:** Execute HTTP and CLI scenarios without browser automation. For backend endpoints: use `fetch()` or child_process to run curl-equivalent requests against localhost. For CLI commands: spawn the CLI with test arguments. Capture response bodies, status codes, stderr, exit codes. Compare against expected outcomes from the scenario. Report pass/fail per step with detailed error context.

### REQ-124: Browser Scenario Execution (Playwright)
**Priority:** P2 — Medium
**Category:** Execution
**Description:** Execute browser-based scenarios using Playwright MCP tools when available. Scenarios include: navigate to page, fill form fields, click buttons, verify DOM state, check console errors. Guard all browser execution behind `playwright_available` detection (check if Playwright MCP tools exist). When Playwright is unavailable, skip browser scenarios with a clear skip reason and suggest manual testing steps instead.

### REQ-125: Test Data Generation
**Priority:** P1 — High
**Category:** Core
**Description:** Generate realistic test data for wireup scenarios. Analyze schema definitions, database models, API request/response types, and form validation rules to produce valid test payloads. Write generated data to `.planning/milestones/{milestone}/wireup/test-data/` as JSON fixtures. Data should be reusable across wireup iterations and committable for integration test suites.

### REQ-126: Missing Connection Detection
**Priority:** P1 — High
**Category:** Analysis
**Description:** After executing scenarios, analyze failures to classify them: missing route registration, unconnected event handler, missing import/export, incomplete form submission handler, missing API middleware, broken navigation link, missing environment variable. Each detected issue gets a structured report with: issue type, file locations (source and target), suggested fix, and confidence level.

### REQ-127: Auto-Fix Capability
**Priority:** P2 — Medium
**Category:** Execution
**Description:** For high-confidence missing connections (e.g., missing import, unregistered route, missing export), attempt automated fixes. Use a sonnet-tier agent to generate and apply the fix, then re-run the failed scenario to verify. Track fix attempts and outcomes. Do not auto-fix low-confidence issues — report them for manual review instead. All fixes are committed with `wireup: fix <description>` commit messages.

### REQ-128: Wireup State Management
**Priority:** P1 — High
**Category:** Infrastructure
**Description:** Track wireup progress in `WIREUP-STATE.json` at project root (parallel to EVOLVE-STATE.json). State includes: features discovered, scenarios generated, scenarios passed/failed, fixes applied, iteration history. Support `readWireupState()`, `writeWireupState()`, `advanceWireupIteration()` functions. State persists across sessions and milestones.

### REQ-129: Wireup Iteration Report
**Priority:** P2 — Medium
**Category:** Reporting
**Description:** After each wireup iteration, generate a structured report: features tested, scenarios run, pass/fail counts, issues found, fixes applied, remaining unwired features. Write report to `.planning/milestones/{milestone}/wireup/WIREUP-REPORT.md`. Append iteration history for trend tracking. Include actionable next steps.

### REQ-130: MCP Tool Registration
**Priority:** P1 — High
**Category:** Infrastructure
**Description:** Register wireup MCP tools in the MCP server: `grd_wireup_discover` (discover unwired features), `grd_wireup_run` (execute wireup iteration), `grd_wireup_state` (read/write state), `grd_wireup_scenarios` (list generated scenarios), `grd_wireup_report` (get latest report). Follow existing MCP tool patterns from evolve.

### REQ-131: Sonnet-Tier Model Ceiling
**Priority:** P1 — High
**Category:** Infrastructure
**Description:** All wireup subagent spawns use sonnet-tier models at most (no opus agents), matching the evolve command's model ceiling (REQ-59). This keeps wireup iterations cost-effective for autonomous/repeated execution.

## Testing

### REQ-132: Wireup Unit Tests
**Priority:** P1 — High
**Category:** Testing
**Description:** Unit tests for all wireup functions: discovery engine, scenario generation, scenario execution (mocked HTTP/CLI), state management, missing connection detection. Per-file coverage threshold of 85%+ lines. Tests mirror `lib/wireup.ts` → `tests/unit/wireup.test.ts`.

### REQ-133: Wireup Integration Tests
**Priority:** P2 — Medium
**Category:** Testing
**Description:** Integration test that runs a full wireup iteration on a test fixture project with known unwired features. Validates the complete flow: discover -> generate scenarios -> execute -> detect issues -> report. Uses the testbed pattern established in v0.2.7.
