    Add a new section `// ─── Artifact DAG Types (from deps.ts) ────────────────────────────────────` after the PlanArtifact interface block in lib/types.ts.

    Define the following interfaces:

    1. **ArtifactDAGNode** — a node representing a plan's artifact declarations:
       - `id: string` — unique plan identifier (e.g., "94-01")
       - `plan_number: number` — numeric plan number
       - `provides: string[]` — artifact names this plan produces (e.g., ["lib/deps.ts:buildArtifactDAG", "lib/types.ts:ArtifactDAG"])
       - `requires: string[]` — artifact names this plan depends on
       - `integration_points: string[]` — integration surface declarations

    2. **ArtifactDAGEdge** — a directed edge representing a requires→provides dependency:
       - `from_plan: string` — plan that requires the artifact (consumer)
       - `to_plan: string` — plan that provides the artifact (producer)
       - `artifact: string` — the artifact name creating this edge
       - `type: 'requires' | 'integration'` — whether this is a hard dependency or integration point

    3. **ArtifactDAG** — the complete artifact dependency graph:
       - `nodes: ArtifactDAGNode[]`
       - `edges: ArtifactDAGEdge[]`
       - `sorted_plans: string[]` — topologically sorted plan IDs
       - `providers: Record<string, string>` — map from artifact name to providing plan ID

    4. **ArtifactDAGValidation** — result of DAG validation:
       - `valid: boolean`
       - `cycles: string[][]` — each inner array is a cycle path
       - `missing_deps: Array<{ plan: string; artifact: string }>` — requires with no provider
       - `warnings: string[]` — non-fatal issues (e.g., unused provides)

    Export all interfaces with `export interface`.

    ```typescript
    import type { DependencyGraph, DependencyNode, DependencyEdge, ArtifactDAG, ArtifactDAGNode, ArtifactDAGEdge, ArtifactDAGValidation, PlanArtifact } from './types';
    ```

    **buildArtifactDAG(plans: PlanArtifact[]): ArtifactDAG**

    1. Build a `providers` map: iterate all plans, for each `provides` entry, map `artifact_name → plan_id` (format plan_id as `"{phase}-{plan_number}"` using the plan's `phase` and `plan` fields, zero-padded to 2 digits). If two plans provide the same artifact, use the first one encountered (later duplicates become warnings in validation).

    2. Build `ArtifactDAGNode[]` from plans: each plan becomes a node with its provides, requires, integration_points.

    3. Build `ArtifactDAGEdge[]`: for each plan, for each entry in `requires`, look up the provider in the `providers` map. If found, create an edge `{ from_plan: consumer_id, to_plan: provider_id, artifact, type: 'requires' }`. For `integration_points`, do the same with `type: 'integration'` (but only if a matching provider exists — integration points are soft dependencies).

    4. Topological sort using Kahn's algorithm (reuse the pattern from `computeParallelGroups` already in the file): build adjacency list from edges, compute in-degrees, iteratively remove zero-in-degree nodes. Store result in `sorted_plans: string[]`. If a cycle prevents full sorting, return the partial sort (validation will catch the cycle).

    5. Return `{ nodes, edges, sorted_plans, providers }`.

    **validateArtifactDAG(dag: ArtifactDAG, plans: PlanArtifact[]): ArtifactDAGValidation**

    1. **Cycle detection** via DFS (reuse the pattern from `detectCycle` already in the file): build adjacency from `dag.edges`, walk with visiting/visited states, collect all distinct cycles found (not just the first one). Each cycle is `string[]` of plan IDs ending with the start node repeated (e.g., `["94-01", "94-02", "94-01"]`).

    2. **Missing dependency detection**: for each plan, for each `requires` entry, check if `dag.providers[artifact]` exists. If not, add `{ plan: plan_id, artifact }` to `missing_deps`.

    3. **Unused provides warning**: for each entry in `dag.providers`, check if any plan's `requires` or `integration_points` references it. If not, add a warning string.

    4. **Duplicate provides warning**: during construction (or re-check here), if multiple plans declare the same `provides` entry, add a warning.

    5. Return `{ valid: cycles.length === 0 && missing_deps.length === 0, cycles, missing_deps, warnings }`.

    **Exports:** Add `buildArtifactDAG` and `validateArtifactDAG` to the existing `module.exports` object.

    Follow code style: zero `any`, prefix unused args with `_`, use `Record<string, unknown>` where needed. Use the existing section comment pattern (`// ─── functionName ───...`).
  </action>
