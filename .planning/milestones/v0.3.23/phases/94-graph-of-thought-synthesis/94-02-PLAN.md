    Add a new function `buildWaves` to `lib/parallel.ts` between the `buildParallelContext` function and `cmdInitExecuteParallel`.

    Add new type imports at the top alongside existing ones:
    ```typescript
    import type { ArtifactDAG, PlanArtifact } from './types';
    ```

    **Interface for wave output:**
    ```typescript
    interface WaveAssignment {
      wave: number;
      plans: string[];  // plan IDs in this wave
    }

    interface BuildWavesOptions {
      artifactDAG?: ArtifactDAG;
    }
    ```

    **buildWaves(plans: PlanArtifact[], options?: BuildWavesOptions): WaveAssignment[]**

    Algorithm:
    1. Build a combined dependency set for each plan:
       - Start with explicit `depends_on` (plan IDs this plan lists as prerequisites)
       - If `options.artifactDAG` is provided, for each plan's `requires` entries, look up the provider plan in `artifactDAG.providers`. Add the provider plan ID to the dependency set.
       - This merges both dependency mechanisms into a single constraint set per plan.

    2. Assign waves using Kahn's algorithm (level-based topological sort):
       - Initialize all plans with in-degree based on combined dependency count
       - Wave 1 = plans with no dependencies (in-degree 0)
       - For each subsequent wave, collect plans whose dependencies are all in previous waves
       - Plans without `provides`/`requires` (empty arrays) are treated as if they have no artifact dependencies — they only respect `depends_on` (backward compatible)

    3. Format plan IDs as `"{phase}-{zero-padded plan number}"` (e.g., "94-01") to match the convention used in `buildArtifactDAG`.

    4. Return array of `WaveAssignment` objects sorted by wave number.

    5. If a cycle is detected (remaining plans with unresolvable dependencies), place all remaining plans in the last wave and log a warning to stderr via `process.stderr.write`.

    **Export:** Add `buildWaves` to `module.exports`.
  </action>
