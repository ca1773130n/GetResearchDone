       ```markdown
       <step name="identify_components">
       Identify missing and borrowed components from the analyzed paper.

       **Missing Components** — techniques/modules the paper references but does NOT implement:
       - Components from other papers that are required but not included in the codebase
       - Pre-trained models or datasets from external sources
       - Custom operators or kernels referenced but not provided

       For each missing component, determine:
       - `name`: Component identifier (e.g., "RoPE embeddings", "FlashAttention kernel")
       - `source_paper`: Paper slug or title where it originates
       - `description`: What the component does and why the paper needs it
       - `code_available`: Whether the source paper's code includes this component

       **Borrowed Components** — techniques the paper adopts from prior work:
       - Standard building blocks taken from other papers
       - Loss functions, architectures, or training strategies from prior work
       - Pre-processing or post-processing pipelines from other methods

       For each borrowed component, determine:
       - `name`: Component identifier
       - `source_paper`: Paper slug or title
       - `description`: What the component does
       </step>
       ```

       **Critical dependencies** (code NOT available):
       - [component]: [why it's critical, what breaks without it]

       ## Borrowed Components

  <files>agents/grd-phase-researcher.md</files>
  <action>
    Update the grd-phase-researcher agent prompt in three locations:

    1. **In `<execution_flow>`, add a new step between Step 4 (Design Experiment Approach) and Step 5 (Recommend Verification Strategy):**

       ```markdown
       ## Step 4.5: Citation Recovery Pass

       If `${research_dir}/PAPERS.md` exists and contains Missing Components or Borrowed Components sections:

       1. **Build citation graph:**
          ```bash
          # The buildCitationGraph function from lib/citations.ts parses PAPERS.md
          # and produces citations/{paper-slug}.json files
          node -e "const { buildCitationGraph } = require('./lib/citations'); const g = buildCitationGraph('${research_dir}'); console.log(JSON.stringify({nodes: g.nodes.length, edges: g.edges.length, unresolved: g.nodes.filter(n => !n.resolved).length}))"
          ```

       2. **For each unresolved node with priority 'critical' or 'normal':**
          - Search for the referenced paper:
            ```
            WebSearch: "[source_paper title]" arxiv
            WebSearch: "[source_paper title]" semantic scholar
            ```
          - If found, fetch abstract and method summary:
            ```
            WebFetch: [arxiv abstract page URL]
            WebFetch: [semantic scholar API URL]
            ```
          - Extract the relevant technique description
          - Mark the node as resolved in the citation graph JSON

       3. **Update citation graph files:**
          - Write updated `citations/{paper-slug}.json` with resolved:true and technique_summary populated
          - Log recovery results: how many nodes resolved, how many remain unresolved

       4. **Gate check:**
          - If any node has `priority: 'critical'` and `resolved: false` after recovery attempt:
            - Log warning: "Critical unresolved citation dependency: {node.slug}"
            - If citation gate is enabled in config (`.planning/config.json` → `citation_gate: true`):
              - BLOCK: Return structured message indicating planning cannot proceed
              - List all critical unresolved dependencies
            - If citation gate is disabled (default):
              - WARN: Continue planning but flag unresolved critical dependencies in RESEARCH.md
       ```

    2. **In the `<output_format>` section**, add a new section to RESEARCH.md template after `## Production Considerations`:

       ```markdown
       ## Citation Recovery

       ### Citation Graph Summary
       - **Total nodes:** [N] papers in graph
       - **Resolved:** [N] papers with technique summaries
       - **Unresolved:** [N] papers still pending
       - **Critical unresolved:** [N] critical dependencies not yet resolved

       ### Resolved Dependencies
       | Paper | Technique | Relevance |
       |-------|-----------|-----------|
       | [slug] | [technique summary] | [why this matters for current phase] |

       ### Unresolved Dependencies
       | Paper | Priority | Why Unresolved | Impact |
       |-------|----------|----------------|--------|
       | [slug] | [critical/normal/low] | [reason] | [what breaks without it] |

       ### Gate Status
       **Citation gate:** [enabled/disabled]
       **Planning blocked:** [yes/no]
       **Reason:** [if blocked, which critical dependencies remain]
       ```
