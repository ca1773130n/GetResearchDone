  <name>Task 1: Define benchmark types in lib/types.ts and scaffold lib/benchmark.ts with TDD RED tests</name>
  <files>lib/types.ts, lib/benchmark.ts, tests/unit/benchmark.test.ts</files>
  <action>
    Add the following interfaces to a new "Benchmark Types" section at the end of lib/types.ts (before the module.exports):

    1. **IntegrationCategory** — string literal union type:
       `'directly-integrable' | 'requires-external-models' | 'out-of-scope' | 'novelty-coverage'`
       Adapted from NERFIFY-BENCH Figure 7 paper categorization by implementation difficulty.

    2. **TrainabilityMetrics** — interface:
       - `build_success: boolean` — whether the generated code compiles/builds without errors
       - `runtime_stable: boolean` — whether execution completes without crashes
       - `convergence_detected: boolean` — whether training/optimization converges (if applicable)
       - `execution_time_ms: number` — wall-clock execution time in milliseconds
       - `error_log: string` — captured stderr/error output (empty string if none)

    3. **SemanticScore** — interface:
       - `novelty_capture: number` — 0-1 score for how well the code captures the paper's novel contributions
       - `api_surface_match: number` — 0-1 score for alignment between paper's described interface and generated code
       - `algorithmic_fidelity: number` — 0-1 score for correctness of core algorithm implementation
       - `notes: string` — optional free-text notes from evaluator

    4. **ScoringRubric** — interface:
       - `semantic_weight: number` — weight for semantic dimension (0-1, all weights sum to 1)
       - `trainability_weight: number` — weight for trainability dimension
       - `category_adjustments: Record<IntegrationCategory, number>` — per-category difficulty multiplier (1.0 = neutral)

    5. **BenchmarkEntry** — interface:
       - `id: string` — unique identifier (typically paper slug)
       - `title: string` — paper title
       - `source: string` — source reference (arXiv ID, DOI, or URL)
       - `category: IntegrationCategory` — integration difficulty classification
       - `tags: string[]` — domain/method tags for filtering
       - `added_at: string` — ISO 8601 timestamp when entry was added to corpus

    6. **BenchmarkResult** — interface:
       - `entry_id: string` — references BenchmarkEntry.id
       - `semantic: SemanticScore` — semantic implementation scoring
       - `trainability: TrainabilityMetrics` — build/run/convergence metrics
       - `composite_score: number` — weighted composite score (0-1)
       - `rubric_version: string` — which ScoringRubric version was used
       - `evaluated_at: string` — ISO 8601 timestamp
       - `evaluator: string` — who/what produced this result (agent name or 'manual')

<task type="auto">
  <name>Task 2: Implement benchmark functions (GREEN) and add coverage threshold</name>
  <files>lib/benchmark.ts, jest.config.js</files>
  <action>
    Implement all five functions in lib/benchmark.ts:

    **loadCorpus(corpusDir: string): BenchmarkEntry[]**
    - If corpusDir does not exist, return []
    - Read all .json files in corpusDir using fs.readdirSync + fs.readFileSync
    - Parse each as BenchmarkEntry, skip files that fail JSON.parse (log warning to stderr)
    - Return sorted by added_at descending (newest first)

    **saveCorpusEntry(corpusDir: string, entry: BenchmarkEntry): void**
    - Create corpusDir if it does not exist (fs.mkdirSync recursive)
    - Write entry as pretty-printed JSON to path.join(corpusDir, `${entry.id}.json`)

    **scoreComposite(semantic: SemanticScore, trainability: TrainabilityMetrics, rubric: ScoringRubric, category: IntegrationCategory): number**
    - Compute semantic sub-score: average of novelty_capture, api_surface_match, algorithmic_fidelity
    - Compute trainability sub-score: weighted sum of build_success (0.4), runtime_stable (0.3), convergence_detected (0.3) — each boolean maps to 0 or 1
    - Composite = (semantic_sub * rubric.semantic_weight + trainability_sub * rubric.trainability_weight) * rubric.category_adjustments[category]
    - Clamp result to [0, 1] using Math.min(1, Math.max(0, composite))

    **createDefaultRubric(): ScoringRubric**
    - semantic_weight: 0.6 (semantic fidelity matters most for paper-to-code synthesis)
    - trainability_weight: 0.4
    - category_adjustments: { 'directly-integrable': 1.0, 'requires-external-models': 0.85, 'out-of-scope': 0.5, 'novelty-coverage': 0.9 }
    - The adjustments reflect that out-of-scope papers inherently score lower (they require capabilities beyond code synthesis), while directly-integrable papers have no penalty

    **formatBenchmarkReport(results: BenchmarkResult[], entries: BenchmarkEntry[]): string**
    - Build a markdown report with:
      - H2 heading: "## Benchmark Results"
      - Summary line: "{N} entries evaluated"
      - Markdown table: | Paper | Category | Semantic | Trainability | Composite |
      - For each result, look up entry by entry_id to get title and category
      - Semantic column: average of the three semantic sub-scores (formatted to 2 decimal places)
      - Trainability column: "PASS"/"FAIL" based on build_success AND runtime_stable
      - Composite column: composite_score formatted to 2 decimal places
      - Final row: average composite score across all results
    - Return the full markdown string

