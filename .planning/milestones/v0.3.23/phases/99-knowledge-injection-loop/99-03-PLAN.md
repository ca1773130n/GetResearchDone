<objective>
Enhance knowledge relevance scoring with phase-proximity boosting and automatic module hint extraction. Currently `selectTopEntries` sorts by recency with optional keyword hints. This plan adds: (1) `extractModuleHints` to auto-derive relevant module names from PLAN.md frontmatter, and (2) phase-proximity scoring so entries from nearby phases rank higher than distant ones within the same recency tier.

Purpose: Better relevance means agents get the most applicable patterns. A phase modifying `lib/autopilot.ts` should preferentially see patterns sourced from autopilot-related phases, and recent-but-nearby entries should outrank recent-but-distant ones.
Output: Enhanced `selectTopEntries` with phase-proximity, `extractModuleHints` function, updated tests.
</objective>

    1. **`extractModuleHints(phaseDir: string): string[]`**
       - Use `fs.readdirSync(phaseDir)` to find files matching `*-PLAN.md` pattern.
       - For each PLAN.md, read content with `safeReadFile`.

    2. **Enhance `selectTopEntries` signature:**
       ```typescript
       function selectTopEntries(
         entries: KnowhowEntry[],
         n: number,
         moduleHints?: string[],
         currentPhase?: number,
       ): string[]
       ```

       In the sort comparator, after the existing `phase_number` descending sort:
       - If `currentPhase` is provided and `a.phase_number === b.phase_number`:
         - Compare `Math.abs(a.phase_number - currentPhase)` vs `Math.abs(b.phase_number - currentPhase)` — closer to currentPhase ranks higher.
       - This is a TERTIARY sort (after recency, after hint match) so it only breaks ties.

       Wait — re-reading the existing sort: it sorts by `phase_number` descending first, then by hint match. Phase-proximity only matters as a tiebreaker when phase_numbers differ but are in the same "tier". Actually, since phase_number is already the primary sort and each entry has a unique phase_number in practice, phase-proximity is better applied as a weight within the hint-match secondary sort.

       Simpler approach: when `currentPhase` is provided, add proximity as a third tiebreaker after phase_number desc and hint match:
       ```typescript
       const sorted = [...entries].sort((a, b) => {
         // Primary: phase_number descending (recency)
         if (b.phase_number !== a.phase_number) {
           return b.phase_number - a.phase_number;
         }
         // Secondary: hint match
         const hintDiff = (hintMatches.has(b) ? 1 : 0) - (hintMatches.has(a) ? 1 : 0);
         if (hintDiff !== 0) return hintDiff;
         // Tertiary: proximity to current phase (closer = better)
         if (currentPhase !== undefined) {
           return Math.abs(a.phase_number - currentPhase) - Math.abs(b.phase_number - currentPhase);
         }
         return 0;
       });
       ```
