<objective>
Implement a merge queue coordination primitive and restructure the autopilot loop so post-phase pipelines run concurrently — with only the rebase+merge step serialized through the queue.

Purpose: Currently post-pipelines run fully sequentially (one pipeline finishes before the next starts). This wastes time because simplify/PR/review steps are independent across phases. Only rebase+merge must serialize to prevent concurrent rebase race conditions on main.

Output: `createMergeQueue()` factory in lib/autopilot.ts, restructured `runPostPhasePipeline()` accepting a merge queue parameter, updated autopilot wave loop launching pipelines concurrently.
</objective>

    1. Create a `createMergeQueue()` factory function near the top of the module (after the domain types section). It returns a `MergeQueue` interface with a single method:
       - `enqueue<T>(fn: () => Promise<T>): Promise<T>` — adds `fn` to a FIFO queue. Only one enqueued function executes at a time. Returns a promise that resolves with fn's result when it completes.
       Implementation: maintain a promise chain. Each enqueue appends to the chain: `this.tail = this.tail.then(() => fn())`. This guarantees serial execution in arrival order with zero external dependencies.

    2. Add a `MergeQueue` interface:
       ```
       interface MergeQueue {
         enqueue<T>(fn: () => Promise<T>): Promise<T>;
       }
       ```

    3. Modify `runPostPhasePipeline()` signature to accept an optional `mergeQueue` in its opts parameter:
       ```
       opts: {
         timeout?: number;

         log: (msg: string) => void;
         mergeQueue?: MergeQueue;
       }
       ```

    4. Restructure `runPostPhasePipeline()` internals: Steps 1-3 (simplify, PR, code review) remain as-is, running sequentially within each pipeline. Step 4 (rebase+merge, starting at the `// Step 4: Rebase & merge` comment) must be wrapped in `mergeQueue.enqueue(async () => { ... })` when a mergeQueue is provided. When no mergeQueue is provided, Step 4 runs directly (backward compatible).

    5. In the autopilot wave loop (around line 1246), change the post-pipeline section:

Specifically: after all execution tasks complete, launch all successful phases' post-pipelines concurrently, passing the shared `mergeQueue`.
